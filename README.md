# clinic-ai-analyst

Месячный цикл финансового аналитика сети клиник, собранный целиком на **синтетических данных**: сверка учёта врачей и касс (ERP) с бухгалтерией (1С), P&L и факторный анализ, деньги, врачи, LTV, прогноз, дашборд, SQL-слой, Excel-трек (Power Query и Power Pivot), ИИ-агент и регламент закрытия месяца.

Сеть вымышленная: 3 клиники, 5 направлений, 2025 год, 66 411 завершённых визитов, выручка 825,2 млн ₽. Цифры показывают работу метода, а не реальную эффективность бизнеса.

Дашборд онлайн: [poliduris1977.github.io/clinic-ai-analyst](https://poliduris1977.github.io/clinic-ai-analyst/). Проект на одной странице: [docs/ONE_PAGER.md](docs/ONE_PAGER.md).

## Запуск
Нужны Python 3.12 или новее и, по желанию, LibreOffice (пересчёт формул в xlsx; без него `check_controls` не прочитает значения формул).

```
pip install -r requirements.txt
python src/run_chain.py
```

Цепочка из 23 шагов (около минуты) создаёт папку `data/`: синтетические данные, сверку, отчёты, дашборд, агента и проверки. Сиды зафиксированы, результат воспроизводится. Подробности и отдельные команды: [INSTALL.md](INSTALL.md).

## Что проверяется
В конце цепочки ожидается:

| Проверка | Результат |
|---|---|
| Агент (`test_agent`) | 44 из 44 |
| Контрольные цифры (`check_controls`) | 40 из 40 |
| SQL-слой (`run_sql`) | 31 из 31 |
| Excel-снапшоты (`check_excel`) | 93 из 93 |
| Сборка дашборда | 87 проверок |

SQL-слой независимо от Python пересчитывает ключевые цифры из исходных таблиц (девять запросов на SQLite). На «грязных» данных сверка находит существенные расхождения, на исправленных их нет.

## Решения для руководства
Четыре вывода из синтетических данных (подробнее на первой вкладке дашборда):
- **План не предусматривал скидки** (коммерческий директор). Скидки года, 12,4 млн ₽, равны фактору «скидки» в мосте маржи; скидку получила примерно пятая часть позиций. Не доказано: окупились ли скидки потоком пациентов.
- **Прогноз по тренду выручки не подходит для косметологии, пластики и лазера** (финансовый и медицинский директора). В пластике скачок сентября шёл вместе с наймом (врачей 4 → 6 за год, 5 → 6 с августа на сентябрь). В косметологии врачей 9 и в августе, и в сентябре, а выручка выросла с 12,7 до 19,8 млн ₽: одним наймом это не объяснить. В лазерной коррекции найма не было, причины в данных нет.
- **Выручка зависит от немногих врачей** (медицинский директор и HR). Десять врачей из 43 дают 38,6% выручки; единственный lead по пластике принёс 10,7 млн ₽ с сентября по декабрь, в ноябре только 0,6 млн.
- **Деньги и клиника C03** (финансовый директор). Доля ДМС в поступлениях у C03 14,9% против 12,0% у C02 и 9,1% у C01, поэтому задержка страховых бьёт по ней сильнее.

За рамками остались отмены и неявки, перекрёстные продажи, окупаемость каналов и бюджет следующего года: для них нужны данные реальной сети.

## Что внутри
- **Сверка ERP и 1С** (`src/reconcile`): 16 типов ошибок, принцип «объясняй и вычитай», исправления с основанием и уровнем уверенности. Слепой тест: второй набор из 14 ошибок написан отдельно от правил; первый прогон 10 из 14 с четырьмя ложными срабатываниями, после доработки правил 14 из 14, но этот результат не слепой ([docs/BLIND_RESULT.md](docs/BLIND_RESULT.md)).
- **Отчёты** (`src/reports`): P&L, план-факт, факторный анализ маржи, врачи, ДДС и ликвидность со стрессом, LTV, прогноз I квартала 2026.
- **Дашборд** (`src/dashboard`): восемь вкладок в одном HTML-файле, без сервера; первая вкладка «Решения» (что видно, что не доказано, кто решает, варианты, что проверить).
- **ИИ-агент** (`src/agent`): шесть вопросов; числа берутся только из проверенных функций. Это каркас с маршрутизатором по ключевым словам, а не языковая модель.
- **SQL** (`sql/`, `src/sql`): девять запросов, описание в [sql/README.md](sql/README.md).
- **Excel-трек** (`excel/`): 22 запроса Power Query (сверка ERP и 1С, три правила ошибок, когортный LTV), модель Power Pivot из шести таблиц, 7 мер DAX (`excel/measures.dax`), две сводные таблицы. В репозитории лежат запросы, меры и два values-only снапшота книги (`dirty` и `corrected`); `src/check_excel.py` сверяет их значения с контрольными (`excel/control_map.json`). Идентификаторы записей в снапшотах скрыты; находки правил проверяются по количеству и суммам. Оговорки: `LTV12` равен 12-месячному LTV только у январской когорты (1 287 пациентов, 34 101,48 ₽), у остальных это выручка за 2025 год на пациента; связи модели описаны по записи, а не проверены по диаграмме.
- **Регламент закрытия месяца**: [docs/REGLAMENT.md](docs/REGLAMENT.md), включая Excel-этап.

## Ограничения
- Данные синтетические; нет данных реальной 1С и CRM, KPI персонала (кроме врачей) не считаются.
- Проверка Excel-трека подтверждает значения снапшотов, а не обновление живой книги: Power Query и DAX в цепочке не выполняются (LibreOffice их не считает), снапшоты собираются вручную в Excel. Сверка в Power Query покрывает выручку «клиника × месяц» и три правила ERP, а не все 16 типов ошибок.
- Прогноз это тренд одного года без сезонности, а не бюджет; по косметологии, пластике и лазеру он ненадёжен.
- Остаток денег дан до налога на прибыль, НДС и дивидендов.
- Исправления средней уверенности требуют подтверждения бухгалтером.

Проект разработан с помощью ИИ-ассистента; решения и допущения записаны.

## Что дальше в реальной сети
Подключить выгрузки живой 1С и ERP, добавить CRM и данные по персоналу, откалибровать допуски сверки на реальных расхождениях, заменить прогноз по тренду моделью с сезонностью и прогнозом по врачам, довести агента до диалога по данным с проверкой каждого числа. Запросить: прибыль по врачу и кабинету, загрузку кабинетов и оборудования, воронку заявок, стоимость привлечения по каналам, маркетинговый календарь, историю за 2–3 года.
